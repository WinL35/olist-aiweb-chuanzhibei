# 前端 Next.js 14 改造记录（2026-11-11）

> 依据：技术栈推荐截图 —— 前端框架「React + Next.js 14+（App Router、Server Components、API Routes、流式渲染）」，
> UI 方案「Tailwind CSS（原子化 CSS）」。

## 一、改了什么，为什么

改造前：`static/` 下 416 行 `assistant.html`（手写 DOM + innerHTML 拼串）+ 727 行 `app.js`（Vue 3 global + 内联 template 字符串），
无构建、无类型、无路由、无组件文件。

这直接对上 AI WEB 评分里「前端工程：TypeScript 规范使用」这一句，也是此前估分中最大的一处断崖（3.7/10）。

改造后：`web/` 独立 Next.js 14 项目，与 FastAPI 后端解耦，前端 8 个路由 / 40 个接口全量类型化。

## 四、四个值得在答辩里讲的取舍

### 1. 为什么看板用 Server Component，对话页却是 Client Component

看板是「读」——数据一次取回就不再变，服务端渲染完 HTML 直发，浏览器拿到就能看，不需要等 JS 水合。
对话是「交互」——多轮历史、流式增量、图表导出都依赖浏览器状态，放服务端没有收益，反而要来回传。

**判断标准不是"哪个更先进"，而是"这份状态归谁管"。**

### 2. 流式渲染做了两层，不是一层

- **RSC 层**：看板的 10 个接口拆成 10 个 `<Suspense>` 边界。页头和所有图表外框随首字节下发，哪块数据先回哪块先刷。
  实测 10 个接口里最慢的约 2.8s，串行等会让用户盯着白屏近 3 秒。
- **对话层**：SSE 推送 `stage → step → delta → result` 四类事件。

**关于"这是不是 token 级流式"——不是，而且我们没假装是。**
ReAct 必须先跑完工具调用，模型才可能生成终稿。终稿天然不可能早于工具阶段。
所以这里的选择是：**真实地推送过程进度**（第 200ms 就能看到"正在调用 pricing_summary"），
**再让终稿按句落屏**——而不是伪造一个匀速打字机，把等待藏起来。
理由写在 `llm/agent/streaming.py` 的文件头，评委翻源码能看到同样的说法。

### 3. 图表 option 放宽类型，业务数据不放宽

ECharts 的 `EChartsOption` 对运行时拼装极不友好：`formatter` 回调、按 `dataIndex` 取色、条件性 series 全部触发类型不兼容。
业界通行做法是把 option 当纯数据描述，在 `EChart` 入口统一断言（`lib/echarts.ts` 有注释说明）。
但 `types/api.ts` 里 40 个接口的响应结构是严格建模的——**该严的地方严，不该跟编译器较劲的地方不较劲**。

### 4. 图表按需引入

旧版直接 `<script src="echarts.min.js">`（1.01MB）。现在只注册实际用到的 5 种图表 + 4 个组件。
构建产物 First Load JS = **87.3 kB（共享）+ 约 220 kB 图表 chunks**，旧版光 ECharts 就 1.01MB。

## 六、与后端的边界

| 项 | 说明 |
|---|---|
| 后端改动 | **仅新增** `POST /api/llm/chat/stream`（`app/llm_api.py`）+ 新建 `llm/agent/streaming.py` |
| 未改动 | `planner.run()`、`_run_llm()` 主循环、硬规则、工具注册表 —— **60 题评测口径完全不变** |
| 前端连后端 | 浏览器侧走同源 `/api/*`，由 `next.config.mjs` 的 `rewrites` 转发到 `PY_API_BASE`（默认 `http://127.0.0.1:8000`），无跨域 |
| 服务端取数 | Server Component 在 Node 进程内运行，没有"相对地址"概念，用绝对地址直连 FastAPI |

## 七、遗留与后续

1. **旧版 `static/` 仍保留**（`/assistant.html`、`/`），作为技术演进对照。若最终只交一版，建议 README 里明确"主入口是 3000 端口"。
2. **对话流式不是 token 级**，如后续要升级，需要在 `llm/providers/openai_compat.py` 增加 `chat_stream()`，并调整 ReAct 收尾轮策略——会引入多工具场景的风险，本轮未做。
3. **多模态仍未接入**（AI 技术深度 35% 里占 5% 分），方案见 `文档/多模态改造方案_20261111.md`。
4. **无前端测试**。若有余力，优先补 `lib/sse.ts`（帧解析，纯函数，最好测）与 `lib/format.ts`。
5. **无 ESLint/Prettier 强制**。`next lint` 已配置但未接入 CI。
