# Olist 电商经营决策平台 · 接口清单

> 后端：FastAPI，`http://127.0.0.1:8000`
> 前端：Next.js，`http://127.0.0.1:3000`
> 在线文档：`/docs`（Swagger UI）、`/redoc`、机器可读 `/openapi.json`
>
> 来源：`app/main.py` 注册 6 个 Router，共 **47 个接口**（含 GET/POST 同路径两种）。
> 本文档按代码实测整理，参数默认值与校验范围均取自源码。

## 0. 全局约定

### 0.1 统一响应结构（异常）

所有异常都被全局处理器包成 HTTP 200 + 业务码，前端只判 `code`：

```json
{ "code": 0,    "message": "ok",   "data": {...} }   // 成功（多数业务接口直接返回 data 本体）
{ "code": 422,  "message": "参数校验失败", "data": [...] }
{ "code": 500,  "message": "服务异常: ...", "data": null }
```

> ⚠️ 注意：`/api/dashboard/*`、`/api/*`（analysis）、`/api/pricing/*`、`/api/selection/*`、
> `/api/experiment/*` 这几个业务路由**直接返回裸对象**（不带 `code/message` 外壳），
> 只有 `/api/llm/*` 与异常路径使用 `code/message/data` 信封。

### 0.2 CORS

`allow_origins=["*"]`，方法/头全放开，可任意前端直连。

### 0.3 数据源

| 库 | 表/视图 | 用途 |
|---|---|---|
| `olist_db` | 13 表 + 10 视图 | 业务宽表（`fact_order_master` / `fact_sales` / `dim_product` / `fact_rfm` / `dim_geolocation`） |
| `olist_algo_db` | 9 表 | 算法1 RFM 标签、算法2 预测/选品/定价/离线实验 |

## 3. 用户分析 /api（app/analysis.py，8 个）

> 前缀是裸 `/api`，路径第二段自带模块名（rfm / conversion / prediction / recommendation）。

### 3.1 RFM 用户分群（读算法1）

| 方法 | 路径 | 参数 | 说明 |
|---|---|---|---|
| GET | `/api/rfm/segments` | `scheme`=`rule8`(默认)/`kmeans4` | 各分群人数、占比、平均 R/F/M、总贡献金额。`rule8`=业务规则 8 类，`kmeans4`=K-Means 4 类 |
| GET | `/api/rfm/scatter` | `limit` 默认 2000，`≤10000`；`scheme` 同上 | 随机采样散点 `[{recency, frequency, monetary, segment, rfm_score}]` |

### 3.2 转化与复购（读业务库）

| 方法 | 路径 | 参数 | 说明 |
|---|---|---|---|
| GET | `/api/conversion/funnel` | — | 五级漏斗 下单→已批准→已发货→已送达→已评价，含 `rate`（相对首级）与 `step_rate`（相对上级）。累积 AND 条件保证单调 |
| GET | `/api/conversion/repurchase` | — | 单次 vs 复购：客户数、客户占比、金额、金额占比、平均频次 |

### 3.3 销量预测（读算法2）

| 方法 | 路径 | 参数 | 说明 |
|---|---|---|---|

| GET | `/api/prediction/sales` | **`category`（必填）**、`weeks` 默认 8，`1~26` | `{history, future[{week,date,forecast,lower,upper,baseline}], metrics{mape_model,mape_baseline,improvement_pct,holdout_weeks}}` |


### 3.4 选品与策略对照（品类级旧口径）

## 4. 定价建议 /api/pricing（5 个，读算法2）

> 关键口径：`suggested_price` / `elasticity` / `price_change_pct` **允许为 null**，
> 含义是「样本不足不给建议」，不是 0。前端用 `has_suggestion` 区分。
> 50 个商品中 31 个有建议价，其中高置信 7 个。

| 方法 | 路径 | 参数 | 说明 |
|---|---|---|---|
| GET | `/api/pricing/summary` | — | 总览：有/无建议价数量、置信度高/中/低分布、提价数与降价数、平均预期收入变化 |
| GET | `/api/pricing/suggestions` | `confidence`=`高`/`中`/`低`；`has_suggestion`=true/false；`category`；`limit` 默认 100，`≤200` | 建议列表，按置信度 + 调价幅度绝对值排序 |
| GET | `/api/pricing/product/{product_id}` | 路径参数 | 单商品定价详情，LEFT JOIN 选品得分（`score_total`/`growth_pct`/`recommendation`） |
| GET | `/api/pricing/skipped` | `limit` 默认 50，`≤100` | 样本不足未给价的 19 个商品明细（`months_observed`/`price_cv_pct`/`reason`） |
| GET | `/api/pricing/by-category` | — | 按品类汇总：商品数、有建议价数、平均现价、平均调价幅度 |

```bash
curl "http://127.0.0.1:8000/api/pricing/suggestions?confidence=高&has_suggestion=true"
```

## 7. 垂直大模型 /api/llm（12 个，app/llm_api.py）

| 方法 | 路径 | 参数 | 说明 |
|---|---|---|---|
| GET | `/api/llm/health` | — | 各层自检：口径库 / 检索 / 工具 / 护栏 / 底座 |
| GET | `/api/llm/tools` | — | 工具清单（`{count, data}`，当前 23 个） |
| GET | `/api/llm/rules` | `topic` 可选，主题模糊过滤 | 行业口径硬规则（含 `wrong` 错误说法、`always` 是否强制） |
| POST | `/api/llm/chat` | body：`question`（必填，≤500 字）、`mode`、`history` | **对话核心入口**，返回完整结构化结果（答案 + 图表 + 引用 + 工具轨迹） |
| GET | `/api/llm/chat` | query：`q`（必填）、`mode` | 同上，GET 版便于 curl / 演示 |
| POST | `/api/llm/chat/stream` | body 同 `/chat` | **SSE 流式，前端主用**，见 7.1 |
| GET | `/api/llm/examples` | — | 示例问题，按「口径题 / 决策题 / 拒答题 / 边界题」四类分组 |
| GET | `/api/llm/eval/questions` | `category`=`A`/`B`/`C`/`D` | 评测题目录（读 `llm/eval/questions.jsonl`） |
| GET | `/api/llm/eval/report` | — | 最近一次评测报告 Markdown 全文 |
| GET | `/api/llm/eval/run` | `limit` 默认 8，`1~40`；`modes` 默认 `baseline,full`（逗号分隔，可选 `no_tools`/`no_rag`） | 在线跑一小批评测（演示用，不写文件） |
| POST | `/api/llm/feedback` | body：`question`（必填）、`answer`、`mode`、`verdict`=`up`/`down`、`correction` | 提交 👍/👎 与纠正，只落库不改规则 |
| GET | `/api/llm/feedback/stats` | — | 反馈统计 |

### 7.1 对话请求体

```json
{
  "question": "美妆这个品类未来 4 周能卖多少？要不要备货",
  "mode": "full",
  "history": [
    { "role": "user", "content": "上个月 GMV 多少" },
    { "role": "assistant", "content": "..." }
  ]
}
```

`mode` 取值：`full`（全量）/ `no_tools`（去工具）/ `no_rag`（去检索）/ `baseline`（纯底座）。
`history` 最多带最近 6 轮，用于多轮追问。

### 7.2 SSE 事件序列（`/api/llm/chat/stream`）

```
event: stage    → 阶段进度（护栏 / 口径 / 检索 / 工具）
event: step     → 单次真实工具调用与耗时
event: delta    → 正文按句增量
event: result   → 完整结构化结果（等价于 /chat 的 data）
event: error    → 出错
```

> 说明：**不是 token 级流式**——ReAct 必须先跑完工具才生成终稿，
> 所以采用「阶段进度 + 终稿按句落屏」。响应头已带 `X-Accel-Buffering: no` 关反代缓冲。

```bash
curl -N -X POST http://127.0.0.1:8000/api/llm/chat/stream \
  -H "Content-Type: application/json" \
  -d '{"question":"哪些商品该降价？","mode":"full"}'

# 普通问答
curl http://127.0.0.1:8000/api/llm/chat?q=GMV%201359%20万，营收也是%201359%20万吧
```

## 10. 已知注意事项

1. **`/api/prediction/sales` 的 `category` 是必填**，且必须用英文品类名（如 `health_beauty`），
   中文名会走到 `{"error": "该品类暂无预测结果"}` 分支（HTTP 仍 200）。
2. **`/api/pricing/*` 的 null ≠ 0**：`has_suggestion=false` 的行代表算法主动放弃，
   前端不要用 0 或空串代替。
3. **`/api/experiment/compare` 的平均 MAPE 只领先基线约 0.1%**，WAPE 甚至略输；
   汇报请引用 `/api/experiment/median` 的中位数口径。
4. **`startswith` 前缀冲突**：`/api/rfm/segments`、`/api/prediction/*` 挂在裸 `/api` 前缀下，
   若后续新增 `/api/xxx` 需确认不与 `dashboard`/`pricing` 等带前缀的 Router 冲突
   （FastAPI 按注册顺序匹配，当前无冲突）。
5. **`/api/llm/tools` 的 summary 写的是「22 个」**，实际注册 23 个；summary 是静态字符串，
   以返回的 `count` 为准。
