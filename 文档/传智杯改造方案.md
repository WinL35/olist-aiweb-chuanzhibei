## 二、他到底有没有接模型？

**没有。现在跑的是「离线确定性规则引擎」，一个大模型都没接。**

证据链：

1. `GET /api/llm/health` 返回：`provider: "offline"`，`model: "offline-rule-engine"`，`has_api_key: false`，`base_url: null`
2. `llm/config.py`：`API_KEY = os.getenv("LLM_API_KEY") or os.getenv("OPENAI_API_KEY") or ""` → 没设环境变量就走 offline 分支
3. 代码里 **没有任何本地模型**：全仓 grep 不到 `torch` / `transformers` / `sentence_transformers` / `ollama` / `vllm`
4. 唯一能出网的地方是 `llm/providers/openai_compat.py`，一个 100 行不到的标准 OpenAI `/chat/completions` 客户端（支持 tool_calls 解析），默认 base_url 指向 `https://api.deepseek.com/v1`、默认模型 `deepseek-chat`——但**没有 key，所以一次都没被调用过**
5. RAG 也不是向量检索：`llm/knowledge/retriever.py` 是 **TF-IDF + 余弦**，纯手写、零依赖（README 自称「239 段文档 RAG（TF-IDF，零依赖）」是准确的）

### 这意味着什么

| 层面 | 现在真正在跑的东西 |
|---|---|
| 「大模型」 | 关键词 → 模板字符串拼接（`composer.py` 747 行规则） |
| 工具调用 | 正则/关键词命中 → 直接调 Python 函数，**不是 LLM 的 function calling** |
| 抗幻觉 | 33 条硬规则 + 引用 `citations`，这个是真的（engine 层实现） |
| 评测 100% / 盲测 75% | 评的是**规则引擎**，不是模型能力（README「诚实声明」里已承认） |

**对兴智杯**：可以，因为兴智杯评的是「方案 + 指标体系」，你在申报书里如实标注了。
**对传智杯**：**不行**。传智杯是作品赛，评委要看到 LLM 真的在推理、Agent 真的在规划。一个「没接模型的规则引擎」在 AIDMX 的「Agent 与大模型技术深度 35%」这一项基本拿不到分。

## 三、兴智杯 vs 传智杯：根本差异

| 维度 | 兴智杯（现在这套） | 传智杯（要投的） |
|---|---|---|
| **交付物形态** | 一份 15 页申报书 PDF，**只看文档** | **代码仓库 + 可运行系统 + 视频 + 技术文档**，四件套 |
| **评价对象** | 方案设计、指标体系、商业模式、社会效益 | 跑得起来吗、有没有真用 LLM、能不能复现 |
| **文档语言** | 政府/商业评审腔（市场分析、商业模式、社会效益） | 工程腔（架构、Prompt 策略、可复现性论证） |
| **过程证据** | 不需要 | **Git 细粒度提交历史 + AI 对话 Prompt 快照**，硬性要求，禁止一次性提交 |
| **视频** | 4 分 53 秒答辩片（已有） | 5–8 分钟 MP4 ≥1080p 普通话，AICXYY 其中 ≥2 分钟必须是「AI 协同过程」录屏 |
| **在线演示** | 无要求 | AIDMX **强制**要公网可访问地址 |
| **复现成本** | 不要求评审自己跑 | 要求评审能一键复现（Docker / 环境变量模板 / 依赖清单） |
| **组别** | — | 广州商学院属**非 985/211 普通本科 → B 组**（可向上报 A 组/研究生组，但不能往下报 C 组） |

一句话：**兴智杯要「想得对」，传智杯要「做得出，且能证明是你做的」。**

## 六、方案 A：投 AI创新应用挑战赛（推荐，改动最小）

### 6.1 评分维度对照

| 维度 | 权重 | 现在能不能拿 | 要做什么 |
|---|---|---|---|
| 过程可复现性与演进链路 | 25% | **0** | 见 6.2 第 1 条，必须补 |
| 解题有效性与实用价值 | 25% | 高 | 电商经营决策是真痛点，已有 44 接口 + 真实数据 |
| 方法创新性与意图控制 | 20% | 中 | 靠「口径即代码 + 三重护栏 + 消融评测」讲创新；但必须接真模型才有「Prompt 工程」 |
| 工程质量与架构设计 | 15% | 中高 | 分层清晰是优点；修 `requirements.txt`、加 Docker、清仓库 |
| 用户体验与产品精细度 | 15% | 中 | 加流式输出 + Agent 思考可视化 + 修路由 |

### 6.2 必做动作（按优先级）

**① 立刻建 Git 仓库，做「可解释的历史」**
- 现在建，别指望一次推完。做法：按模块分 15～30 次真实提交（`feat: 接入 DeepSeek provider` / `fix: 品类意图路由误判` / `refactor: 抽出 tools/registry` …），每次提交一个能讲清的改动
- ⚠️ 诚实底线：不要伪造历史。你 11-07 之前的工作没法追溯，就**如实从今天开始记录**，技术文档里写明「重构/上线阶段（11-07 起）的完整提交历史」，配合真实 Prompt 快照，比伪造一堆日期被识破强
- `.gitignore` 补：`cleaned/`、`算法1/`、`算法2/`、`olist_algo.db`、`*.sql`（大文件改为提供 Kaggle 下载说明 + `pipeline/clean_merge.py` 重建脚本）

**② 接入真实模型（这是本方案的分水岭）**
```bash
# .env.example
LLM_API_KEY=sk-xxx
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL=deepseek-chat
```
- 已有 `openai_compat.py` 直接用，主力改 `llm/agent/planner.py` 的 ReAct 循环（现在有 217 行骨架，但 offline 分支绕过了它）
- **必须做的对比**：同一批问题，offline vs LLM 两条路径都留接口，视频里现场切换——这一手同时证明「我真接了模型」和「我知道规则引擎的边界」
- 合规提醒：**key 只能走环境变量**，`.env` 进 `.gitignore`，仓库里只放 `.env.example`

**③ 修 1.4 里的三个 bug**（route 错误、越界漏拦、拒绝理由文不对题）— 有 LLM 之后大部分自动好了，但要留回归测试

**④ 流式输出**：`/api/llm/chat` 加 SSE 分支（`stream: true`），前端 `EventSource` 渲染 token + 显示「正在调用工具：dashboard_summary…」的步骤条

**⑤ 部署上线**：Dockerfile + docker-compose（app + mysql 一体），起一个公网地址（哪怕临时隧道），README 里写「10 分钟极速复现」

**⑥ 材料三件套**
- 视频 5–8 分钟：0–2min 讲痛点+架构；2–5min **录屏演示 AI 协同过程**（展示你怎么用 Prompt 让 AI 生成 planner 的 ReAct 循环、怎么带它修一个真实 bug —— 就用 1.4 那个路由 bug，真实且有说服力）；5–7min 功能演示
- 技术文档 ≤30 页：`意图控制策略`（system prompt 怎么约束工具选择）、`架构设计`（五层怎么解耦、AI 生成的代码被什么规则约束住）、`可复现性论证`。**把兴智杯那份的「消融实验 0%→83.3%→100%」「盲测 75%」搬进来**，改写成模型能力评测——这是你相对其他选手的硬优势
- Prompt 快照：导出 3 条完整链（提问原文 → AI 回复 → 你的引导 → 最终代码），截图或 md 存档放 `docs/prompts/`

## 七、方案 B：投 AI大模型创新应用挑战赛（科研助手）

固定命题，六大模块。好消息是**架构几乎 1:1 可迁移**，坏消息是领域要整个换掉。

### 7.1 架构映射表

| 传智杯模块 | 现有可复用资产 | 需新建 |
|---|---|---|
| 一、PDF 管理 / 细粒度解析（语义去重、OCR、标题树、公式、表格） | `tools/registry.py`+`executor.py` 的工具挂载模式；`db.py` 存取封装 | PyMuPDF/pdfplumber 解析、rapidocr 扫描件 OCR、**语义去重直接用 `retriever.py` 的 TF-IDF 余弦**做 v1 vs v7 比对（现成能力，评委很难想到） |
| 二、抗幻觉问答（RAG + 多文推理 + 出处锚点） | `hard_rules.py`（33 条口径硬规则 → 换成学术口径）、citations/snippets 已有引用结构 | 页码/段落级锚点（现在只到「文档名 + 章节标题」）、跨文献对比 prompt |
| 三、版式感知阅读 + 双向联动翻译 | — | **全新，前端重活**：双栏还原、`[11]`↔References 双向跳转、中英联动滚动 |
| 四、自动检索 / arXiv 追踪 / 推荐 | 工具层机制、`pipeline` 的 pandas 处理能力 | arXiv API、S2/Crossref、去「应付式引用」的启发式筛选 |
| 五、引用图谱 + 综述生成 | `app/analysis.py` 的聚合查询套路 | **networkx + PageRank/中介中心性**、Future Work 抽取去重、自动综述 |
| 六、写作辅助 + 可视化 Copilot | **ECharts 前端 + pandas 出图能力可直接复用**；LLM 生成代码正好是 Agent 主场 | TikZ/Graphviz/Mermaid 脚本生成、CSV→学术图表→Figure Caption |

### 7.2 现实建议

六大模块全做完在 11 天内不现实。**按分值砍**：

- 必做（占分最高）：模块二（抗幻觉 8% + 图谱创新 10% + 溯源）+ 模块五（图谱 10%）
- 必做（最容易出彩）：模块一里的**语义去重**——官方给了 `1706.03762v1.pdf` vs `v7.pdf` 的标准用例，你现成的 TF-IDF 余弦就能跑，这是「测试用例通过率 5%」里最稳的一分
- 可简化：模块三翻译只做「划词翻译 + 整篇译」跳过联动滚动；模块六只做 Mermaid 不做 TikZ
- 明确放弃并写进文档：OCR（扫描件）如果时间不够，就诚实说明「未覆盖 `_img.pdf` 用例」

> 坦白讲：方案 B 更可能出「技术亮点」，但 11 天内做出完整闭环的风险很高，容易变成「六个模块都只有壳」。**建议主投方案 A，方案 B 作为国赛（12 月 27 日截止）的二期目标。**

## 附：实测环境备忘

```bash
# 实际可跑的启动方式（本项目实测通过）
export MYSQL_PASSWORD=123456          # config.py 默认写的是 root，与本机不符
python -m pip install -r requirements.txt requests
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
# 前端 http://127.0.0.1:8000/    对话 http://127.0.0.1:8000/assistant    文档 /docs
```

> 注：项目目录名末尾含 **不间断空格（U+00A0）**，不是普通空格。部分工具/脚本按普通空格处理会找不到路径，改名前请留意。
