## 〇、三句话

1. **投 AI WEB，最大的问题不是功能缺，是「身份不对」**：材料通篇写着个人赛《选题 8》，README 没有团队信息，前端页面底部还挂着「选题八 · AI 数据分析与可视化」。AI WEB 是 **1–3 人同校团队赛 + 自由选题**，报名信息和材料口径必须先改，否则是资格层面的问题。
2. **第二条是「形态不对」**：官方特别说明原文——「作品须以**前端 Web 应用为主要呈现形态**，后端服务仅作为 AI 能力的**接入层**，不作为重点考察对象」。实测后端 Python 11,686 行 vs 前端 1,657 行（**87% : 13%**），评委 clone 下来看到的是一个数据分析后端 + 两张静态 HTML。
3. **第三条才是「功能缺」**：真正被评分点名而完全没做的有两项 —— **多模态（5%）0 分**、**流式输出（AI 交互 3% 里的一条）缺失**；前端工程 10% 是断崖（约 3.7/10）。

按现有状态直接投，估分 **63–67 / 100**；补齐前端工程 + 流式 + 最低成本多模态，可到 **77–80**。

## 四、三个结构性错位（比缺功能更值钱）

### 错位 1：赛道要「前端为主」，项目是「后端为主」

官方原文：「作品须以前端 Web 应用为主要呈现形态，后端服务仅作为 AI 能力的接入层，不作为重点考察对象。」
实测：py 11,686 行 : 前端 1,657 行 = **87% : 13%**。不修这条，评委的默认印象就是「AI 数据分析后端套了层网页皮」——前端 10% 只拿 3.7 是**结果**，不是原因。

### 错位 2：技术栈离推荐列表太远

推荐：React + Next.js 14（首选）/ Vue 3 + Nuxt 3 / React + Vite / SvelteKit / Astro；UI 用 Tailwind + shadcn/ui；AI 交互用 Vercel AI SDK / LangChain.js；状态管理 Pinia/Zustand；SSE/WebSocket 流式。
现状：**FastAPI + 原生 HTML + Vue global（CDN 版）+ 手写 fetch**，无 `package.json`、无构建工具、无 npm 生态。

> 「技术选型不做强制限定」，但 25% 创新 + 10% 前端工程是主观分，选型离推荐越远，解释成本越高。**已选 Vue 3 是加分项，把它升到「Nuxt/Vite + SFC + TS + Pinia + AI SDK」只差工程化。**

### 错位 3：个人赛口径的遗留物

`提交清单.md`（个人赛 5 项材料）、`static/index.html` 侧栏「选题八」、`答辩材料/答辩PPT.pptx`（兴智杯旧版，无 AI 协同）。这些不删不写，评委看到的是「别的赛道的材料被复用」。
