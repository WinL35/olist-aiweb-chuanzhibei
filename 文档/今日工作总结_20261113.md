## 二、四小人对视动画

### 2.1 需求演变

需求经过三轮澄清才收敛，核心难点在于**我从截图/描述里读错了动作方向**：

- 第一轮理解：紫柱压矮去「仰视」黑柱 ❌
- 用户给 19s 录屏并要求「认真看」后才纠正：紫柱是**拉高**、眼睛在黑柱**左上方**

### 2.2 从录屏逆向量出的真实参数

用 `ffmpeg` 抽帧 + numpy 色块分析，逐帧测量原始动效：

| 指标 | 测量结果 | 折算 |
|------|----------|------|
| 紫柱顶边 y | 124 → 66 | **+58px = 柱高 +13%** |
| 紫柱顶边右端 x | 230 → 431 | 右甩 201px = 柱宽 86% |
| 紫柱底边 | 几乎不动 | 以底边为轴 `scaleY` |
| 紫眼相对黑眼高度 | 高 176px | ≈ 柱高 39% |

### 2.3 最终实现

**三阶段包络**（靠过去 → 定住对视 → 撤离）：

```tsx
const APPROACH_MS = 380;
const GAZE_MS = 3380;      // 对视精确 3 秒
const RETREAT_MS = 3900;
```

横向位移 `x` 只在前半段（`reach`）生效，避免「原地拔高」的错觉：

```tsx
const e = elapsed < APPROACH_MS
  ? easeOut(elapsed / APPROACH_MS)
  : elapsed < GAZE_MS
    ? 1
    : 1 - easeInOut((elapsed - GAZE_MS) / (RETREAT_MS - GAZE_MS));
const reach = elapsed < GAZE_MS ? e : 0;
```

紫柱动作（拉高 + 右甩 + 脸下压对齐内眼）：

```tsx
T.purple = {
  x: +6 * reach,        // 右移让紫右眼贴到黑左眼
  skew: -6.5 * reach,   // −10° 会盖住黑柱 13px，收敛到 −6.5°
  stretch: 13 * e,      // 拉高 13%
  faceY: 13 * e,
};
T.black = { faceY: -4 * e };  // 负值=往上抬
```

### 2.4 对视判据（关键教训）

前几版我验的是「有没有被遮挡 / 柱子歪没歪 / 紫有没有拉高」，**从没验过两只眼睛是否真的对上**，导致反复返工。

改用三项量化判据后收敛：

| 判据 | 修复前 | 修复后 |
|------|--------|--------|
| 紫右眼 cy vs 黑左眼 cy | 差 26.5px | **差 8.84px** |
| 横向间隙 | 分离 | **0.75px** |
| 瞳孔间距 | — | 6.25px |

**终态实测**：静立紫柱 h=70.3 / 对视 h=232（×1.13）；1.0s→3.3s 数值恒定（确为 3 秒）；4.5s 复位。

### 2.5 图层铁律

对视时曾把紫 `zIndex` 1→2、黑 2→1，导致紫柱下半身从橙柱后面冒出，且盖住黑柱眼睛。

**修复：整段动态 zIndex 删除，层级永久固定 紫1 / 黑2 / 橙3 / 黄4。**

> 教训：`z-index` 是剪影骨架，永远不要为了让局部露出来而交换层级。

## 三、原生下拉框改胶囊下拉（PillSelect）

### 3.1 为什么必须自建

原生 `<select>` 的弹出层是**浏览器独立绘制的一层**（Chromium 里甚至不在 DOM 中），CSS 完全无法命中它的背景、边框和 `<option>`。截图里那个方框 + 蓝底高亮**改不掉**，只能自己实现。

### 3.2 视觉实现

- **触发器**：胶囊形，展开时箭头 `rotate-180` 并变主色
- **面板**：**0px 边框**，只有深底 `#141d2e` + 22px 圆角 + 柔和阴影
- **选项**：`rounded-full` 全胶囊（中间长条 + 两端半圆），无边框
- **逐条滑入**：`animation + animationDelay` 错峰，`26ms` 一条

```css
@keyframes pillOptionIn {
  from { opacity: 0; transform: translateX(-14px) scale(0.97); }
  to   { opacity: 1; transform: translateX(0) scale(1); }
}
```

用 `animation` 而非 `transition`：元素展开时才挂载，`transition` 没有初始态容易不触发；`animation` 天然支持 `animationDelay`。

## 四、今日修复的三个 Bug

### Bug 1：选项提示气泡点击后不消失（原生 title）

**现象**：悬停选项 → 原地点击 → 面板关闭，但气泡一直挂着，必须移动鼠标才消失。

**根因**：原生 `title` 属性 = 浏览器 tooltip，**只在收到鼠标事件时消失**。选项 DOM 已卸载、光标原地不动 → 浏览器收不到新事件。且 **JS 无法主动关掉原生 tooltip**。

**修复**：删除所有 `title`（触发器改用 `aria-label`），改为 hover 时 `setState` 的自绘 tooltip，`close()` 与点外部关闭里 `setTip(null)`。

**验证**：全页 `[title]` = 0；悬停 1 个 → 原地点击后 **0** 个。

---

### Bug 2：面板背景透明（Tailwind 任意值 + 透明度失效）

**现象**：下拉展开后 K 线图直接透上来。

**根因**：`bg-[#141d2e]/96` 实际解析为 `rgba(0,0,0,0)`。

**修复**：背景色改写 inline style 硬赋值。

### Bug 3：侧栏导航气泡点击后不消失（真凶）

> ⚠️ 这个 Bug 我**第一轮修错了对象**——改的是下拉的 `title`，但用户说的「点任意一个」指的是**左侧导航栏图标**，那是另一套代码。

**真凶**：`fluid-tooltip-engine.ts` 的 `onLeave`

```ts
if (this.buttons.some((b) => b === document.activeElement)) return; // 永收不起
```

本意是「键盘操作时持焦，别收」，但**鼠标点击导航后焦点同样会留在那个链接上**，于是鼠标移开了判断仍然命中，直接 `return`。

**实测复现**：鼠标移到 `(900,700)` 内容区，气泡 `opacity` 仍为 `1`，正压着页面标题。

**修复**：引入 `showSource: "pointer" | "focus"`，只有键盘唤起时才允许因持焦保持：

```ts
if (this.showSource === "focus" && this.buttons.some((b) => b === document.activeElement)) return;
```

**判定方式的两次失败尝试**：

| 方案 | 结果 |
|------|------|
| `:hover` | ❌ 同一位置连点会误判，键盘聚焦时气泡不出现 |
| `pointerdown` + `setTimeout` 复位 | ❌ 被上一轮事件残留污染 |
| **`:focus-visible`** | ✅ 规范语义即「键盘/辅助技术引起的焦点」 |

**配套**：`onEnter` 里 pointer 优先、不被后续 focus 降级；`fadeOut()` 里 `showSource = null` 防跨轮累积。

**验证**：

| 用例 | 结果 |
|------|------|
| 鼠标悬停 → 点击 → 移开 | `1.00 → 1.00 → 0.00` ✓ |
| Tab 聚焦（`focusVisible=true`）→ ↓ → Esc | `1.00 → 1.00 → 0.00` ✓ |
| 纯鼠标悬停 → 移开 | `1.00 → 0.00` ✓ |

**顺带修掉**：`destroy()` 的解绑一直无效——绑定时用匿名函数、解绑时传 `this.onEnter`，引用对不上。改为 `handlers[]` 保存引用后精确解绑。

## 七、方法论沉淀

1. **几何验收必须读 DOM `getBoundingClientRect`**，不要靠截图找色——橙色高光 `rgb(255,155,107)` 会被误判成紫色，导致「柱子没动」的错误结论。
2. **动效需求先要录屏，再逐帧测量**，不要从静态描述猜方向。今日最大返工就来自方向猜反。
3. **验收判据要贴着用户措辞**。用户说「对视」，就要验两只眼睛的坐标关系，而不是验柱子有没有歪。
4. **`z-index` 是骨架，不参与动效**。
5. **浮层里的元素不要用原生 `title`**——它不受 React 状态控制，组件卸载也带不走。
6. **「因为有焦点所以不隐藏」这类豁免，必须先判断焦点来历**，否则鼠标点击（同样给焦点）会被误判成键盘操作。
7. **Tailwind 任意值 + 透明度（`bg-[#xxx]/96`）可能静默失效**，关键底色写 inline style。
