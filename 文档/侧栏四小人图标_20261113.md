# 侧栏「智能问答」入口改为四小人图标

日期：2026-11-13
涉及文件：
- 新增 `web/components/nav/nav-characters.tsx`
- 修改 `web/components/nav/fluid-nav.tsx`
- 修改 `web/components/nav/icons.tsx`（移除已无引用的 `IconChat`）

---

## 1. 需求来源与改动点

原型：用户提供的 `animated-login-master`（Vite + React 登录页），核心组件是
`src/components/AnimatedCharacters/index.tsx` —— 紫/黑/橙/黄四根柱子，眼珠追鼠标、
随机眨眼、密码框聚焦时集体闭眼不偷看。

三条需求：

| # | 需求 | 落地做法 |
|---|---|---|
| 1 | 把「智能问答」的图标换成四个小人 | 侧栏底部圆形入口内的 `BrandMark` → `NavCharacters` |
| 2 | 追踪鼠标的功能保留 | 眼球 rAF 逐帧贴向鼠标；不悬停时看鼠标，悬停时看悬停的按钮 |
| 3 | 「点击密码框」的互动触发条件改为「点击导航栏」 | `NavCharacters` 暴露 `pulse`，导航按钮 `onClick` 自增；同时新增悬停侧身 |

## 2. 三处必要改造

### 2.1 从 550×400 插画缩成 26–52px 图标

原作是登录页配图，柱子宽 120–180px。这里按 **100×100 单位坐标系**重写，
坐标全部用百分比表达，外层盒子决定显示尺寸 —— 改尺寸只需改一个 `h-[…] w-[…]`。

换算（原作 550×400 → 100×100，另留 6% 左右内边距）：

| 柱子 | 原作 left/宽/高 | 本项目 left/宽/高 |
|---|---|---|
| 紫 | 70 / 180 / 400 | 6+9% / 30% / 100% |
| 黑 | 240 / 120 / 310 | 6+44% / 19% / 75% |
| 橙 | 0 / 240 / 200 | 6% / 42% / 48% |
| 黄 | 310 / 140 / 230 | 6+58% / 24% / 56% |

图层 `紫 z1 → 黑 z2 → 橙 z3 → 黄 z4`，橙色遮住紫色下半身 —— 这就是原作里
「紫色只露出上半截、脸上显得很高」的来源，不能改顺序。

### 2.2 GSAP quickTo → rAF 指数插值

原作 20 个通道全用 `gsap.quickTo`。图标只有 26px，为它引 70KB 的 GSAP 不划算
（本项目 First Load JS 共享包只有 87.3 kB）。

改写成「每帧把当前值推向目标值 18%」（`BODY_EASE = 0.18`），瞳孔用 0.6
（眼睛本来就该比身体跟得快）。视觉与原作同属减速跟随，分不出差别。

> 曾试装 `gsap@3.14` 验证，装好后卸载 —— 依赖树没留痕（`package.json` 已无 gsap）。

### 2.3 触发语义改成本项目的场景

图标旁边没有账号/密码输入框，原作的两个触发点重新映射：

| 原作 | 本项目 |
|---|---|
| 鼠标移动 → 眼珠追 | **保留**，常驻 |
| 账号框聚焦 → 歪头看 | **悬停导航按钮** → 四小人一起侧身，`gazeRatio`（0=顶部/1=底部）决定倾斜方向 |
| 密码框聚焦 → 集体闭眼 | **点击导航按钮** → 触发一次「对视」：紫往右下、黑往左上，身体错开，350ms 复位 |

`NavCharacters` 只吃 props（`hovered` / `gazeRatio` / `pulse`），不读外部 DOM 状态，
换触发源只要改传参。

## 3. 踩过的三个坑（都是 CSS 层，值得记）

### ① flex + 百分比宽度的眼睛会消失

最初用 `<div className="flex justify-between">` 放两只眼，眼睛宽高写 `34%`。
在宽度 3–9px 的柱子里，flex 会按内容尺寸算百分比，结果宽度收缩到 0，**眼睛直接看不见**
（截图里橙、黄两人是光脸）。

→ 改成 `absolute left-0 / right-0` 定位，宽度基准是脸部容器。

### ② `height: <百分比>` ≠ 正方形

`width: 34%; height: 34%` 里，height 的百分比是相对 **父元素高度** 算的。
脸容器只有 9–14% 高 → 眼睛变成扁横条。

→ 也不要用 `aspect-ratio`（父容器高度受限时仍会被压扁），
改用 `padding-bottom: <同宽度百分比>; height: 0` 的经典方形技巧。

### ③ 深色 UI 上白色低透明度分隔线会「发蓝」

这个坑此前已经踩过一次（侧栏右缘 `rgba(255,255,255,.10)` 被读成蓝线）。
这次是同类问题：小人的黑色柱子在 `#35363a` 上几乎融进背景。
→ 给整体加 `filter: drop-shadow(0 1px 1.5px rgba(0,0,0,.55))` 把轮廓托起来，
而不是加一层白底圆（用户明确要求去掉白底）。

---

## 4. 视觉决策：去掉白色圆底

初版把四小人放进原来的白底圆形按钮里。实测两处不好：

1. 小人本身带颜色，白底上像「一张缩略图贴在圆里」，不像图标；
2. 与上方 7 个线性图标（26px 描边、无底色）放在一起，量级和语言都不统一。

最终：**入口改为透明热区 84×84 + 图形本体 52px**，与上方按钮同宽同行距；
悬停给 `bg-white/[.06]` 底，选中给 `bg-white/[.11]` + 1.5px 内描边。

## 6. 后续可调项

- 想要更「活泼」：把 `BODY_EASE` 提到 0.28、`pulse` 时长从 350ms 拉到 500ms。
- 想要更大/更小：只改 `fluid-nav.tsx` 里的 `h-[52px] w-[52px]`，内部坐标全是百分比。
- 眨眼：原作有 `gsap.to(height: 2)` 的随机眨眼，本次未搬（26px 下眨眼不明显，
  且会额外占用帧）。若需要，用 CSS `@keyframes` 对眼白做 `scaleY` 即可，不占 JS 帧。
