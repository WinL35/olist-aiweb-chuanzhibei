# 数据集说明（Olist 巴西电商公开数据集）

> 对应 PDF 交付材料中的「数据集说明」。本文说明数据来源、规模、字段、清洗规则与统计口径，
> 便于评审在不看代码的情况下判断数据是否被正确使用。

## 一、数据来源与许可

| 项 | 内容 |
|---|---|
| 数据集 | Brazilian E-Commerce Public Dataset by Olist（Kaggle） |
| 内容 | 2016-09 ~ 2018-10 巴西电商平台约 10 万笔真实订单，含客户、卖家、商品、支付、评价、地理位置 |
| 许可 | CC BY-NC-SA 4.0，仅用于教学与非商业研究 |
| 原始体积 | 9 个 csv，约 100 MB（交付包不附带原始文件，理由见第四节） |

## 四、为什么仓库不带原始数据

原始 csv 约 100 MB，Kaggle 许可禁止再分发；清洗结果 `cleaned/` 有 128 MB，直接提交会让仓库体积翻数倍、clone 变慢，
因此两者都不进 git 历史。

**获取方式**：下载 Release `v1.0.0` 的附件 `cleaned.zip`（52 MB），解压到项目根目录即为 `cleaned/`，
再执行 `python 一键导入主库.py`；如需从零重建，把原始 csv 放进 `Dataset/` 后执行 `python pipeline/clean_merge.py`。

## 五、清洗规则与已处理的数据问题

| 问题 | 处理 |
|---|---|
| 日期格式混用 `2017/01/01` 与 `2017-01-01` | 统一 `pd.to_datetime`，解析失败置空 |
| 订单重复 | 按 `order_id` 去重 |
| 商品品类名缺失 | 填 `unknown`，再用翻译表补英文名；仍缺失则保留葡语原名 |
| 商品尺寸重量缺失 | 用列中位数填充（保留记录，避免丢单） |
| 评价一对多 | 按 `review_answer_timestamp` 取最晚一条 |
| **未评价订单** | `review_score` 保持空值（入库为 NULL），**不填 0**——0 不是合法星级，填 0 会把平均分从 4.086 拉低到 4.055 并污染评分分布 |
| 支付 `not_defined` | 丢弃该支付类型（3 个订单因此无支付汇总，金额按 0 计，已在质量报告注明） |
| 地理表一行一坐标 | 按邮编前缀取经纬度均值、城市/州取首条 |
| 城市名重音 | 统一去重音（`são paulo` → `sao paulo`），避免同城多种写法 |
| 州代码大小写 | 保持大写（`SP`/`RJ`），前端地区地图按大写代码匹配 |

## 六、统计口径（与接口、文档一致）

| 指标 | 口径 |
|---|---|
| GMV | `fact_order_master.gmv` 求和 = 13,591,643.70 BRL（商品金额，不含运费） |
| 订单数 | `COUNT(DISTINCT order_id)` = 99,441（含各状态，不筛 `delivered`） |
| 客单价 | GMV / 订单数 = 136.68 BRL |
| 复购率 | 下单次数 > 1 的用户 / 用户总数 = 3.05%（`customer_unique_id` 口径，95,420 人） |
| 送达率 | `order_status='delivered'` / 订单数 = 97.02% |
| 平均评分 | `AVG(review_score)`，忽略 NULL = 4.0864 |
| 订单漏斗 | 下单 → 已批准 → 已发货 → 已送达 → 已评价（累积口径），99,441 → 99,281 → 97,644 → 96,461 → 95,815 |
| 周维度 | 按 `purchase_date` 现算 ISO 周 `%x-W%v`（`purchase_week` 只是周序号，跨年不可单独排序） |

## 七、已知局限（答辩可主动说明）

1. **无浏览/加购日志**：漏斗只能用订单时间戳近似（下单→批准→发货→送达→评价），不是真实站点转化率。
2. **复购率天然偏低（3.05%）**：Olist 是"一次性平台"属性，该指标用于分群参考而非考核。
3. **时间范围不均**：2016-09~12 数据量极少（平台早期），预测训练窗从 2017-01 起更稳。
4. **价格弹性样本有限**：单商品价格变动少，故 log-log 弹性只对 31/50 个商品给出建议价，其余明确标注"数据不足"。
