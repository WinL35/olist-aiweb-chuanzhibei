# Olist 电商经营分析与智能选品平台

## 1. 项目概述

中小电商商家通常难以把订单、商品、用户和评价数据转化为可执行的经营动作。本项目基于 Olist 巴西电商公开数据集，建设一套“数据分析 + 智能决策”一体化平台，帮助商家观察经营状况、识别用户价值、预测品类销量，并形成选品和定价建议。

目标用户为中小电商运营人员与商品运营人员。平台运行于本地单机环境，采用 Vue 3 + ECharts、FastAPI 和 MySQL。

## 2. 需求对应

| 题目功能 | 系统实现 |
|---|---|
| 经营与行为看板 | GMV、客单价、订单数、客户数、送达率、复购率、支付转化率，以及趋势、品类、区域、支付、评价等图表。 |
| 用户分群 | 以真实用户 `customer_unique_id` 为粒度，提供 RFM 规则 8 类与 K-Means 4 类分群。 |
| 转化分析 | Olist 没有浏览行为，采用“下单→批准→发货→送达→评价”的订单漏斗，并分析复购。 |
| 销量预测 | 按品类做未来 1–8 周预测，展示历史值、移动平均基线和 95% 区间。 |
| 选品建议 | 以近期规模和增长性筛选品类，展示 Top10 及两种策略的离线命中率。 |
| 定价建议 | 对可估计价格弹性的商品展示当前价、建议价、价格区间、置信度和预期收入变化；样本不足时明确不给建议。 |
| 离线策略评估 | 前端展示推荐策略命中率及 4 个预测模型的 MAPE、WAPE、MAE、RMSE 对照。 |

## 3. 数据来源、合规与处理

- 主数据源：Olist Brazilian E-Commerce Public Dataset，公开页面：<https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce>。
- 使用前应遵守 Kaggle 与数据发布方的适用条款；本项目仅用于课程实践和数据分析展示，不做个人识别或商业再分发。
- 原始数据包括订单、订单明细、客户、商品、卖家、支付、评价、地理位置和品类翻译 9 张表。
- 清洗后保留 13 张分析表，其中 `fact_order_master` 为 99,441 行，`fact_sales` 为 112,650 行，满足题目不少于 5 万条记录的要求。
- 具体字段含义、缺失值处理、去重规则和宽表构建过程见 [算法1_算法文档.md](算法1_算法文档.md) 与 [数据库设计文档.md](数据库设计文档.md)。

## 4. 系统设计

```text
cleaned/*.csv ──> MySQL 主业务库 olist_db ──> FastAPI ──> Vue + ECharts
      │                                             ▲
      ├──> 算法1：RFM、订单漏斗、复购 ──> olist_algo_db ┤
      └──> 算法2：预测、选品、定价、离线实验 ───────────┘
```

主业务库保留客户、订单、商品、销售、评价等事实/维度表；算法结果库单独存储 RFM 标签、预测、选品、定价和实验结果，使模型迭代不会破坏原始业务数据。数据库表关系、索引和建库流程见 [数据库设计文档.md](数据库设计文档.md)。

## 6. 算法、指标与真实结论

算法1使用 RFM 指标与 K-Means 聚类，补充规则 8 类标签以增强运营可解释性。算法2以移动平均作为基线，并使用 Holt-Winters/阻尼 Holt 等方法做周粒度销量预测；选品基于规模、增长和价格因素，定价使用历史量价关系估计弹性。

预测实验的主模型 MAPE 均值为 135.73%，基线为 136.89%；主模型 MAPE 中位数为 90.46%，优于基线 99.69%，但 WAPE 为 72.59%，略差于基线 68.47%。因此项目只表述为“部分品类优于基线”，不宣称整体显著优于基线。详细结果、评价口径与局限见 [算法2_算法文档.md](算法2_算法文档.md)。

## 8. 运行与验收

安装依赖、导入数据库、启动服务及冒烟测试命令见 [README.md](../README.md)。验收时应检查：

1. `/api/health` 的业务库与算法库均为 `ok`；
2. 七个页面均能加载数据且无控制台报错；
3. `python scripts/smoke_test.py` 全部通过，核心接口单次响应不高于 2 秒；
4. 定价页面将“数据不足”显示为无建议，而不是 0；
5. 演示和文档中的指标与算法 CSV 保持一致。

最近一次本地冒烟与单次响应记录见 [验收记录.md](验收记录.md)。

## 9. 局限与后续优化

Olist 不包含浏览、加购或实时库存数据，因此订单漏斗只能近似真实行为路径，选品也未纳入库存/利润约束。周粒度销量较稀疏，预测误差较高；后续可增加节假日、促销、毛利和库存特征，按稳定品类分层建模，或改用月度预测作为经营决策辅助。
