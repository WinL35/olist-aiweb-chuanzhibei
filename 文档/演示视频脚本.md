# 演示视频脚本（5–8 分钟 · 1080p）

> 官方硬要求：MP4、≥1080p、5–8 分钟、普通话配音。
>
> 建议时长 **7 分 30 秒**，按下面的分镜录。每段都给了口播稿，可照读。
>
> **本版（2026-11-14）重写原因**：旧版脚本里的"看板右下角浮窗""`assistant.html`"
> "选题 8""个人赛"全部已失效——前端已重构为 Next.js 8 页应用，静态页已从仓库移除。
> 若照着旧稿录，画面和口播会双双对不上。

## 录制前准备（15 分钟）

**环境**

1. 后端已启动：`python 启动后端.py`（8000 端口）
2. 前端已启动：`cd web && npm run dev`（3000 端口）
3. 浏览器打开 `http://127.0.0.1:3000/dashboard`
4. 浏览器缩放 **100%**、窗口 **1440×900** 以上（1080p 录屏下表格不糊）

**录屏设置**

- Windows 自带：`Win + G` → 捕获 → 分辨率选 1080p
- 或 OBS：输出 1920×1080、30fps、码率 6000kbps、录制格式 mp4
- 麦克风先试录 10 秒回听，确认没有电流声

**提前打开 4 个窗口（避免录制时切错）**

| 窗口 | 内容 |
|---|---|
| ① 浏览器标签 A | `http://127.0.0.1:3000/dashboard`（经营看板） |
| ② 浏览器标签 B | `http://127.0.0.1:3000/assistant`（智能问答） |
| ③ 编辑器 | `文档/Prompt快照.md`（AI 协同复现用） |
| ④ 终端 | 项目根目录，待会儿要重放 `git log` 与一个真实 Bug |

**录前预热（重要）**

- 先在标签 B 随便问一句，让 Next.js 完成路由编译、模型连接热起来；
  否则第一个问题会卡在编译上，看起来像"AI 很慢"。
- 确认 `.env` 里 `LLM_API_KEY` 有值（`GET /api/llm/health` 返回 `has_api_key=true`）。
  若为 false 会走离线引擎，回答带 `provider=offline` 标注，可用但不够有说服力。

## 分镜 3｜1:40–4:00　核心链路：一句话出一张图（2 分 20 秒）

### 3.1 提问与出图（1:40–2:45）**← 核心镜头**

**操作**

1. 按 `Ctrl+8` 跳到智能问答页（让快捷键在镜头里用一次）
2. 点示例 chip「**各品类GMV画柱状图**」
3. 等 5–7 秒（**别剪掉等待**，评委要看 AI 真的在跑；SSE 阶段进度会依次亮起）
4. 图出来后，鼠标沿 y 轴数值划过；再展开下方【数据依据】

**口播**

> 我直接问："把各品类的 GMV 画成柱状图"。
>
> 注意这个过程提示：先调 `dashboard_category` 取数，再调 `render_chart` 出图，
> 最后组织结论——它是**流式推过来的**，每一步都看得见，不是转圈等到最后一下全出来。
>
> 五秒多，图出来了。图注自动标了口径：GMV 等于商品单价求和、不含运费、货币是巴西雷亚尔。
>
> 这里最关键：**图上的每个数字都不是模型写的**。模型只能决定"画成柱状图、横轴品类、
> 纵轴 GMV"，数值是后端从工具返回里确定性组装的。所以这张图能直接放进汇报，经得起核对。

### 3.2 多轮追问（2:45–3:10）

**操作**：接着输入「**那第二名是谁？**」

**口播**

> 再追问一句："那第二名是谁？"——它记得上一轮结果，直接答出 watches_gifts，
> GMV 一百二十万零五千，还给出和第一名的差值。数字同样来自上下文里的工具返回。

### 3.3 取数轨迹与口径（3:10–3:45）

**操作**：滚到右栏「取数轨迹」与「口径与依据」面板，逐条指过去

**口播**

> 需要复核的时候看右边：这是取数轨迹，每一步调了哪个工具、参数是什么、成功还是失败；
> 下面是口径与依据，这条回答依赖了哪几条硬规则、检索命中了哪几段文档。
> 这是我留给评委的复核入口，AI 说的每句话都能往回追。

### 3.4 数字可核对（3:45–4:00）

**操作**：新标签打开 `http://127.0.0.1:8000/api/dashboard/category`，对比图上 y 值

**口播**

> 最后一个动作，验证一下：直接打开取数接口，health_beauty 一百二十五万八千，
> 和图上那根最高的柱子完全一致。**图和接口是同一个源。**

## 分镜 4｜4:00–6:20　**AI 协同过程复现**（2 分 20 秒）

> 这段是 AI 技术深度的评分重点。**不要只讲"我用了 AI"，要现场复现"我怎么指挥 AI"。**

### 4.1 展示 Prompt 快照（4:00–4:40）

**画面**：编辑器打开 `文档/Prompt快照.md`，滚动展示几条链的标题

**口播**

> 开发全程用 AI 编程助手，我的角色是定义问题、验收结果、判断取舍；
> AI 的角色是调研、实现、自测。所有对话整理成了 Prompt 快照，每条都包含：
> 我提的问题、AI 的判断、它改了哪些代码、以及**我们踩到的真实 Bug 和排查过程**。

### 4.2 复现一次关键设计（4:40–5:30）

**画面**：停在 `render_chart` 那段引用上，逐字念出关键约束

> **图表里的每个数字必须来自工具返回值，模型只被允许决定「画什么」，不允许提供「画多少」。**
> 新增 `render_chart(chart_type, data_from, x_field, y_fields)`，参数里没有数据字段……

**口播**

> 这是我当时给 AI 的约束。它的建议是：不要让模型直接吐 ECharts 的数据，
> 而是让工具参数里**根本没有数据字段**，只能指定"用哪个工具的既成结果"。
>
> 我追问："如果模型没先查数就直接画呢？"它就加了这条校验——
> `data_from` 本轮没被调用过，工具直接报错。
>
> 这一句话把"不许编数"从**提示词约束**变成了**代码约束**。
> 提示词模型会破例，代码不会。

### 4.3 现场重放一个顽固 Bug（5:30–6:20）**← 最有说服力的一段**

**画面**：终端，依次执行（录制前先跑一遍确认输出）

```bash
git log --oneline | head -12
git show --stat f74349d
git show f74349d -- llm/agent/guard.py | head -40
```

**口播**

> 举个真实 Bug。SQL 护栏里写了一份"允许查询的视图白名单"，十个视图名。
> 我一直以为它是好的，直到让 AI **去数据库里核对**，而不是看代码——
> 它查了 `information_schema`，发现这十个名字里**只有三个真的存在**，
> 比如代码写的是 `v_order_funnel`，库里其实叫 `v_order_master`。
>
> 如果没发现，等接了自然语言转 SQL，护栏会疯狂误拦，
> 看起来像"模型不会用工具"，实际是白名单写错了。
> 这是我学到最有用的一课：**验证要去真实数据源，不要信代码注释。**
>
> 修复就是这一次提交，`f74349d`，只改了视图名，但把整条链路的可用性从 0 拉到 100。

## 分镜 5｜6:20–7:10　架构与评测（50 秒）

**画面**：`文档/技术文档.md` 的 §2.1 分层表

**口播**

> 架构上前后端分工很清楚。前端是 Next.js 应用，八个路由、图表组件、SSE 解析、
> Tailwind 设计令牌，是作品的**主要呈现形态**；后端只做 AI 接入层：
> ReAct 循环、23 个工具、33 条口径硬规则、239 段检索，再加三重护栏。
>
> 数据层是 23 张表加 10 个视图，另有 9 张算法结果表。
>
> 评测是 60 题主集加 20 题盲测，四种消融模式。
> 接入真实模型后：主集 **91.7%**，盲测 **100%**。
> 有意思的是离线规则引擎反过来：主集 100%、盲测只有 75%——
> 那是过拟合的假象，因为主集的问法它都"见过"。
> 真实模型在没见过的问法上反而更好，说明它在做语义理解，不是模式匹配。
