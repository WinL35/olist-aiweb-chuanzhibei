# 多模态改造方案（AI WEB · 补 5% 空白项）

> 制定时间：2026-11-11　目标赛点：AI WEB 评分细则「AI 技术深度 35% → **多模态能力 5%**」
> 原文考察点：**「是否集成多种模态（文本、图像、语音、视频），多模态融合是否自然流畅」**
> 现状：**0 分**（全仓无 vision / audio / 语音 / 图像输入；ECharts 出图不算多模态）
> 预算：**最小可用 1 天 / 完整 2 天**，投入产出比 0 → 3 分

---

## 〇、先说结论：多模态不是加个上传按钮

评分的两个关键词是「**多模态**」和「**融合是否自然**」。绝大多数参赛作品的做法是：上传图片 → 丢给 VL 模型 → 把返回的一大段话粘到聊天框里。这叫**拼接**，不叫融合，评委一眼能看出来，因为「然后把这张图怎么办」是没有下文的。

本项目有一个别人没有的天然优势——**33 条口径硬规则 + 图表数据后端确定性组装**（模型不许编数字）。所以最自然、也最能加分的融合方式是：

> **图片进来的不是一段文字描述，而是被结构化、随后被口径规则校验过的事实；这份事实会继续驱动定价/选品工具和出图，和文字提问走同一条 Agent 链路。**

一句话版本：**视觉只做「读数」，不做「决策」；决策仍然走原来的 ReAct + 口径护栏。**

这条叙事同时抬两个分：多模态 5%（有真链路）+ 技术方案创新 8%（与"模型不许编数字"一脉相承）。

## 一、三条路线对比（先选路线，再写代码）

| 路线 | 做法 | 成本 | 演示稳定性 | 得分 | 建议 |
|---|---|---|---|---|---|
| A. 纯前端 Web Speech | `webkitSpeechRecognition` 语音转文字 | 0 元 / 2 小时 | ⚠️ **差**：Chrome 走 Google 服务，国内基本连不上 | 语音 1 项，勉强 1.5–2 分 | 不单独用，只作 TTS 补充 |
| B. 图像结构化 + 语音播报（**推荐**） | 图片 → VL 模型抽 JSON → 注入 Agent；结论用 `speechSynthesis` 播报 | 免费额度够 / **1 天** | ✅ 稳（VL 走 API，TTS 走本地） | **3 分** | **最小必做** |
| C. B + 后端 ASR 语音输入 | 浏览器录音 → 后端转写（SenseVoice / Whisper）→ 文本进同一条链 | 很低 / +0.5 天 | ✅ 稳 | 3.5–4 分 | 有余力再加 |

**视频模态**：不建议做真的视频理解。文档里写一句「视频以抽帧方式复用图像通道，本版本未开放，列入后续规划」即可——诚实标注比硬凑一个假入口得分高。

## 二、关键技术前提（先说的坑，避免白干）

| 坑 | 说明 | 对策 |
|---|---|---|
| **DeepSeek 不支持读图** | `deepseek-chat` 是纯文本模型，`image_url` 会被拒 | **必须配第二套 VL 端点**，复用现成的 `OpenAICompatProvider`（只需换 `base_url/model/key`） |
| OpenAI 兼容的图片格式各家用得一样 | `{"type":"image_url","image_url":{"url":"data:image/png;base64,..."}}` | 智谱 GLM-4V-Flash / 通义 qwen-vl / 硅基流动 Qwen2.5-VL **全兼容**，换模型不改代码 |
| Web Speech 识别在国内不可用 | 依赖 Google 语音服务 | 语音**输入**走后端 ASR；语音**输出**用 `speechSynthesis`（本地合成，可用） |
| 图片体积 | base64 直传容易顶到 10MB 限制、拖慢响应 | 前端 canvas 压到 **长边 1024px、JPEG 0.8**，上限 1.5MB |
| offline 模式怎么办 | 项目有「无 key 走规则引擎」的传统，评委会问断网场景 | 无 vision key 时**隐藏上传入口并显式提示**，而不是让用户传了图得到一个假答案 |
| 成本 | GLM-4V-Flash 有免费额度；SenseVoice 约 ¥0.0007/秒 | 演示 10 次以内，成本可忽略；`.env.example` 写清可选 |

**推荐的具体服务（都 OpenAI 兼容，注册即用）**

| 用途 | 服务 | base_url | model |
|---|---|---|---|
| 视觉 | 智谱 GLM-4V-Flash（免费） | `https://open.bigmodel.cn/api/paas/v4` | `glm-4v-flash` |
| 视觉（备选） | 硅基流动 | `https://api.siliconflow.cn/v1` | `Qwen/Qwen2.5-VL-7B-Instruct` |
| 语音转写 | 硅基流动 | `https://api.siliconflow.cn/v1` | `FunAudioLLM/SenseVoiceSmall` |

### 步骤 2｜新建 `llm/providers/vision.py`（约 90 行）

**核心设计：强制 JSON 输出 + 读不出就填 null，禁止推测。** 这是把"模型不许编数字"的原则延伸到图像通道。

```python
# -*- coding: utf-8 -*-
"""视觉通道：把图片抽成结构化事实，不做任何推断。

为什么不用「让 VL 模型自由描述图片」：
自由描述会带出「看起来大约 30 元左右」这类猜测，一旦被下游定价工具采用，
就变成"AI 编出来的价格驱动了商业建议"——与本项目「图表数字必须来自工具」
的底线冲突。所以这里只允许模型做 OCR + 版面归类，字段固定、读不出填 null。
"""
import base64, json, requests
from llm import config
from llm.providers.base import ProviderError

_SCHEMA_PROMPT = """你是电商数据录入员，只做"读数"，不做推断。请从这张图片中抽取结构化事实。

只输出一个 JSON 对象，不要任何解释文字、不要 markdown 代码块。字段固定：
{
  "kind": "competitor_price | product_photo | table_screenshot | order_screenshot | other",
  "items": [{"name": "", "price": null, "currency": "", "rating": null, "sold": null, "date": ""}],
  "table": {"headers": [], "rows": []},
  "confidence": 0.0,
  "unreadable": ["看不清的字段名"]
}

规则：
1. 任何看不清/不存在的字段填 null，**禁止猜测、禁止估算**；
2. price 只填数字（不带货币符号），currency 单独填（如 BRL / CNY）；
3. 图片与电商经营无关时 kind=other、items=[]；
4. table 只在整张图是表格时填，否则留空。"""


def extract(image_bytes: bytes, mime: str = "image/png") -> dict:
    """图片 → 结构化事实。失败抛 ProviderError，由上层降级，不阻断主链路。"""
    if not config.VISION_API_KEY:
        raise ProviderError("未配置 VISION_API_KEY，多模态通道未启用")

    b64 = base64.b64encode(image_bytes).decode()
    payload = {
        "model": config.VISION_MODEL,
        "temperature": 0,                      # 抽取任务不要发散
        "messages": [{"role": "user", "content": [
            {"type": "image_url",
             "image_url": {"url": f"data:{mime};base64,{b64}"}},
            {"type": "text", "text": _SCHEMA_PROMPT},
        ]}],
        "stream": False,
    }
    r = requests.post(f"{config.VISION_BASE_URL.rstrip('/')}/chat/completions",
                      json=payload, timeout=config.VISION_TIMEOUT,
                      headers={"Authorization": f"Bearer {config.VISION_API_KEY}"})
    if r.status_code != 200:
        raise ProviderError(f"视觉底座 HTTP {r.status_code}: {r.text[:200]}")

    text = r.json()["choices"][0]["message"].get("content") or ""
    text = text.strip().removeprefix("```json").removeprefix("```").removesuffix("```").strip()
    try:
        data = json.loads(text)
    except json.JSONDecodeError as e:
        raise ProviderError(f"视觉模型未返回合法 JSON：{e}") from e

    data.setdefault("kind", "other")
    data.setdefault("items", [])
    data["_meta"] = {"model": config.VISION_MODEL, "bytes": len(image_bytes), "mime": mime}
    return data
```

### 步骤 3｜`llm/agent/prompts.py`：把事实注入上下文（8 行）

```python
def messages(question, mode="full", rules=None, snippets=None,
             history=None, image_facts=None) -> list[dict]:
    ...
    um = user_message(question)
    if image_facts:
        # 用「事实块」而不是「描述」，并且显式告诉模型 null 的含义，

        um["content"] += (
            "\n\n【图像识别事实】以下由视觉模型抽取，未经口径校验，仅作事实输入，"
            "禁止对其中的数值做二次推算：\n"
            + json.dumps(image_facts, ensure_ascii=False)
            + "\n注意：字段为 null 表示图中不可辨认，**必须如实说明无法读取，禁止推测**。"
        )
    msgs.append(um)
    return msgs
```

### 步骤 5（可选，路线 C）｜`/api/llm/asr`（约 40 行）

```python
from fastapi import UploadFile, File

@router.post("/asr", summary="语音转写（浏览器录音 → 文本）")
async def asr(file: UploadFile = File(...)):
    audio = await file.read()
    if len(audio) > 8 * 1024 * 1024:
        return _fail("录音过大（上限 8MB）", 400)
    r = requests.post(f"{config.ASR_BASE_URL.rstrip('/')}/audio/transcriptions",
                      headers={"Authorization": f"Bearer {config.ASR_API_KEY}"},
                      files={"file": ("a.webm", audio, "audio/webm")},
                      data={"model": config.ASR_MODEL}, timeout=30)
    if r.status_code != 200:
        raise HTTPException(502, f"ASR 失败: {r.text[:200]}")
    return {"ok": True, "text": (r.json().get("text") or "").strip()}
```

/* 图片：选文件 / 粘贴 / 拖拽 三种入口都给，演示时最稳的是粘贴（Ctrl+V） */
async function toB64(file) {
  // 为什么要压缩：手机拍的原图 3–5MB，base64 后膨胀 33%，会顶到网关限制并拖慢响应
  const img = await createImageBitmap(file);
  const scale = Math.min(1, 1024 / Math.max(img.width, img.height));
  const c = document.createElement("canvas");
  c.width = img.width * scale; c.height = img.height * scale;
  c.getContext("2d").drawImage(img, 0, 0, c.width, c.height);
  return c.toDataURL("image/jpeg", 0.8).split(",")[1];
}

/* 语音播报：本地合成，零成本、断网可用 */
function speak(md) {
  const text = md.replace(/[*#`>|]/g, "").slice(0, 400);
  const u = new SpeechSynthesisUtterance(text);
  u.lang = "zh-CN"; u.rate = 1.05;
  speechSynthesis.cancel(); speechSynthesis.speak(u);
}

## 四、验收标准（做完拿这四条自检）

| # | 动作 | 通过标准 |
|---|---|---|
| 1 | 上传一张竞品价格截图，问「按这些竞品价给我建议定价」 | 返回里出现**图里真实存在的品牌/价格**，且随后调用了 `pricing_*` 工具（`trace` 里能看到） |
| 2 | 上传一张模糊图 | 答案明确说「图中 X 字段无法辨认」，**不出现编造数字** |
| 3 | 不配 `VISION_API_KEY` 启动 | 前端不显示 📎；手工调接口返回 400 + 可读原因；**纯文本问答完全不受影响** |

第 1、2 条就是「融合自然」的证据——**能证明图像事实真的流进了工具链，而不是被当成一段文本贴上来**。

## 六、优先级建议（7 天里不要为它挤掉前端工程化）

| 顺序 | 内容 | 工时 | 分值 |
|---|---|---|---|
| 1 | 图像结构化链路（步骤 1–4） | 1 天 | **0 → 3**（多模态 5% 的主体） |
| 2 | 方案 C 语音输入（步骤 5 + 录音按钮） | +0.5 天 | 3 → 3.5 |
| 3 | 文档补一节「多模态技术方案」+ 视频加 40 秒 | +0.3 天 | 撑住「多模态融合」的表述分 |

> **不要做的**：为了凑"视频模态"去接抽帧识别——工时 1 天以上，评分边际几乎为 0。
> **更不要做的**：让 VL 模型直接生成 ECharts 配置或结论数字——会同时打穿「图表数据确定性组装」这个最硬的创新点，得不偿失。
